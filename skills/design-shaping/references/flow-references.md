# Flow references

Formats worth borrowing on any product, by kind of surface, each from an explain-interface read. The competitive look reads the entry for any surface of that kind beside the incumbents. A new entry needs a read of the real flow (frames or the live product), not a screenshot of one moment, and earns its place only if it does something our skills don't already say. Technique is the recipe; Take is what to borrow; Avoid holds the source's own look, since build agents get this text.

## Onboarding (any first-run setup)

### Detent

Source: [28s clip](https://x.com/next_gendev/status/2119335361554030899), read at one frame a second.

- **Technique.** Split screen. Left: one step per screen, four steps (connect tools, invite team, create the first agent, try it out), a headline in two weights ("Connect your tools." bold, then a gray sentence on why), a four-segment progress bar with "Step 2 of 4". Right: "Your workspace, so far", a live preview of the real app that fills in as the user acts. Tools appear in its sidebar, an activity feed logs each action ("You connected GitHub · harbor-labs"), and the people count goes from "Just you" to "4 people". The last step runs the product's first real job on screen as a checklist of honest steps (reading 6 conversations, checking a policy, filing a bug, drafting 4 replies) and ends on its result ("Sorted 6 conversations, drafted 4 replies and filed 1 bug") before "Open Detent".
- **Take.** Onboarding builds the real product, not a checklist about it: every step leaves an artifact the user can see. End on the product's first real result, computed live, so the aha happens before the user leaves onboarding. Fill defaults from what the user already connected (teammates from the GitHub org; templates marked "2 of 3 connected"). Buttons name the consequence ("Skip for now" becomes "Send 2 invites"); Continue waits for the one input the next step needs.
- **Avoid.** Detent's pastel gradient frame and its type. A faked first result. When the product's first result can't be computed during onboarding (it needs a day of data), keep the preview, since what the setup steps add to it is real, and end on the empty state's first action instead of a live job.
